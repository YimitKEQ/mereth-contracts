Each contract is a leaf of the register. The wax seal carries its state, so an unpaid promise reads as a broken seal at a glance. The fee, the funding flag and what you may do about it sit in the ruled margin, which is where a clerk would have written them.

Two ideas carry the weight

One

Funded or unfunded, and everyone can see which

A funded contract takes the coin at the moment it is posted and holds it. The worker is certain of payment. An unfunded one binds nothing: taking it is a bet on the client's word. That single visible flag turns reputation from a number into a question players actually ask each other.

Two

A promise that breaks becomes an object

When an unfunded contract is delivered and the client cannot pay, nothing errors. A debt note is written, sealed, naming both parties and the contract it came from. Anyone can read it. A broken promise stops being a failure state and starts being evidence.

The default path

server/contracts/contract.ts

The engine is pure. It never touches the game, so it is fully testable headless, and it decides nothing about who was right.

Coin is never invented

server/contracts/escrow.ts

Two rules govern everything that moves money. Never create coin: every septim paid out was first taken from somebody. And take before you promise, so a failure leaves no contract rather than an unpayable one.

A player cannot act as somebody else

server/contracts/wire.ts

The client names an action and a contract id. It never names the actor. That comes from the connection, which is the whole authorization story in one line.

It reaches the player with nothing installed

no mod, no download

SkyMP lets a server push client-side JavaScript to a player. That code holds the full Skyrim Platform API, so the server renders the board itself. Players install nothing. This runs every frame for the owner, which is why it compares a revision number and does nothing at all in the common case.

What it took to find

undocumented

Four things gate the server-to-client channel. Each one fails silently: no error on either side, the client simply never learns the properties exist. None are in the published docs, and the first exists only as a string inside scam_native.node.

GateWhat you see when it is wrong
enableGamemodeDataUpdatesBroadcast Server logs skipping gamemode data update send and never ships the channel.
server-info-ignore createClientSafe :0. The client resolves no peer and never connects at all.
serverKey + server-public-keys Pushed JavaScript is rejected with no signature found and deleted.
Debug.messageBox A modal box pauses the game loop, and updateOwner only runs on update. Every push freezes while it is on screen.

What a player is called

server/contracts/identity.ts

Worth calling out, because the obvious call is the wrong one and it took a live server to notice. Every player character is built on the same base record, the vanilla player NPC_ at 0x7, which is named Prisoner. So getActorName reported that Prisoner had posted work for Prisoner and Prisoner had taken it.

The name a player chose lives in the character's appearance, and that is the same string SkyMP puts above their head: the client runs refr.setDisplayName(model.appearance.name, true) on every appearance update. The stable identity is profileId, not the form id, which is reassigned on every connect.

Dropping it in

  • One gamemode module. server/contracts/ plus a few lines in your gamemode entry. Pure TypeScript, no ESP, no Papyrus.
  • Two settings. The broadcast flag and a signing key, as above.
  • Optional UI folder. A single HTML file in Data/Platform/UI/ if you want the styled panel rather than the console board.
  • Nothing for players. The board and every action are delivered by the server at runtime.
  • Persistence is free. Contracts live in server properties, so they survive restarts as ChangeForms with no database work.

Honest limits

  • Goods contracts are checked, services are not. The server counts items into the client's hands. A service is settled on the worker's word, which is deliberate: that is the part players should be arguing about, not the server.
  • No arbitration. There is no dispute queue and no staff tooling here. Rejection is recorded against both parties and judged by neither.
  • Chromium is environment-dependent. Both Skyrim Platform browser backends fail on my dev machine, so the console board is what I could photograph. Mereth already pins NirnLab UI Platform, so the styled panel is the path on your install.
  • Tested against a local server. Real skymp5-server, real ESPM data, one connected client. Not yet against Mereth's load or its modlist.
